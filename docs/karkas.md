# Каркас KvizY: как устроено и что где менять

Это карта приложения. Когда захочешь что-то поменять — найди здесь нужный пункт и скажи Claude: «поменяй в `файл` вот это».

---

## 1. Идея и принципы

**Что делает:** ты загружаешь лекции, конспекты, слайды или ссылки → ИИ делает квиз → проходишь его карточками → видишь баллы, слабые темы, рост. По каждому предмету можно собрать большой «квиз по предмету».

**Принципы:**
1. **Квиз проверяет понимание** — промпт прямо требует вопросы про причины, связи, применение.
2. **ИИ пишет только содержание** (вопросы, ответы, объяснения, оценку открытых ответов). Баллы, проверка, статистика, хранение, интерфейс — код.
3. **Экономия:** все вопросы квиза — одним запросом; все плохие вопросы — одним запросом на замену; готовое не спрашиваем заново.
4. **ИИ сменный:** провайдер, модель и ключ меняются в Настройках, без кода.
5. **Ключи только на сервере**, в базе — зашифрованы, на экран обратно не попадают.
6. **Ошибки не молчат:** любая ошибка — сообщение + «Повторить».
7. **Как приложение:** PWA, оболочка открывается из кэша мгновенно.

---

## 2. Путь пользователя

1. **Вход** — пароль один раз на устройство, cookie на год.
2. **Создать квиз** — предмет (подсказки из прошлых), тема, файлы/текст/ссылки, «откуда и докуда», число вопросов, сложность, таймер, подсказки. Форма запоминает прошлые значения (кроме файлов).
3. **Создание** со статусами: «загружаю файлы…» → «читаю файлы…» → «делаю вопросы…» → «проверяю…» → (если нужно) «заменяю неудачные вопросы…».
4. **Прохождение** — карточки по одной, прогресс «5 из 10», серия правильных подряд, таймер, «↻ заменить вопрос» (до 4 раз), подсказка. После ответа карточка зелёная/красная, объяснений нет.
5. **Итог** — %, баллы, % по темам и подтемам, все карточки (тап → вопрос, твой ответ, правильный, баллы, объяснение, цитата). «Пройти снова», «В историю».
6. **История**, **Статистика** (+ «График роста»), **Предмет** (+ «Квиз по предмету»), **Настройки** (ИИ, палитра, пароль, расходы).

## 3. Технологии

| Часть | Что | Почему | Чем можно заменить |
|---|---|---|---|
| Сервер | Python 3.12 + FastAPI + Uvicorn | как в Priz, простой | — |
| Интерфейс | один HTML + CSS + JS, без сборки | нечего ломать, правится с iPad | React/Vue, если сильно вырастет |
| PWA | `manifest.json` + service worker `sw.js` | иконка на «Домой», мгновенный запуск | — |
| Текст из файлов | pypdf, python-docx, python-pptx | надёжно, легко | pdfplumber для сложных PDF |
| Текст со ссылки | httpx + BeautifulSoup | без тяжёлых библиотек | readability-lxml |
| База | SQLAlchemy: SQLite локально, **YDB Serverless** на сервере | YDB бесплатна в пределах квоты, внутри Yandex Cloud | Postgres (Supabase / Yandex Managed PostgreSQL) — достаточно поменять `DATABASE_URL` |
| Миграции | свои простые (`app/migrations.py`) | Alembic плохо дружит с YDB | Alembic |
| Хостинг | Yandex Cloud Serverless Containers | открывается в России без VPN | ВМ в Yandex Cloud |
| Деплой | GitHub Actions → Container Registry → ревизия | пуш в `main` = обновление | — |
| Графики | свой SVG | ноль зависимостей | Chart.js с CDN |

## 5. Данные (таблицы)

У всех данных есть `user_id` (сейчас всегда `owner`) — задел на доступ для других людей.

|---|---|---|

| settings | настройки «ключ → JSON» | `ai.provider`, `ai.<провайдер>.model/folder_id/...`, `key.<провайдер>.api_key` (зашифрован), `palette`, `price.<провайдер>`, `budget`, `form` |

| questions | вопросы | все поля вопроса + `replace_count`, `replace_history`, `source_question_id` (для копий в квизе по предмету) |
| attempts | попытки | `score`, `max_score`, `pct`, `by_topic`, `by_subtopic`, `duration_sec` |
| answers | ответы | `response`, `score`, `correct`, `status` checked/unchecked/timeout, `note`, `time_sec`, `snapshot` (вопрос на момент ответа — его потом могли заменить) |
| usage | каждый вызов ИИ | `provider`, `model`, `purpose`, токены, `cost_rub`, `quiz_id`, `quiz_title` |

**Файлы пользователя не хранятся** — только извлечённый текст.

**Почему файлы грузятся кусками:** у Yandex Serverless Containers один запрос не больше ~3,5 МБ 🟡. Экран режет файл на куски по 2 МБ (`UPLOAD_PART_BYTES` в `config.py`), сервер склеивает.

## 6. Как делается квиз (`app/quiz/pipeline.py → generate`)

1. **Шаг 1 — `POST /api/quizzes`:** текст из файлов, ссылок и вставки → чистка (`material.clean_text`) → метки `[Файл N: имя]`, `[Страница N]`, `[Слайд N]`, `## Заголовок` → обрезка «откуда докуда» (`material.apply_range`) → текст в `quiz_texts`.
2. **Шаг 2 — `POST /api/quizzes/{id}/generate`** (долгий запрос; экран раз в 1,5 с спрашивает `/status` и меняет только строку статуса):
   - `plan_requests` решает, сколько запросов: если текст не влезает в один запрос (у YandexGPT запрос + ответ ≤ 32 000 токенов) или вопросов слишком много для одного ответа — делит текст на куски по заголовкам/слайдам/страницам (`split_text`) и вопросы пропорционально (`allocate`). Тогда на экране «Материал большой…».
   - запрос `quiz`: ИИ сам делит на темы/подтемы и пишет все вопросы.
   - проверка кодом (`questions.problems`): цитата правда есть в тексте (`QuoteIndex`, без учёта регистра, пробелов, знаков, «ё»), у «один из 4» ровно 4 варианта и 1 правильный, у «несколько» 2+ правильных и не все, пары/шаги без повторов, пропуск ___ один, нет дублей, число вопросов = заказу.
   - все плохие + недостающие → **одним** запросом `replace`. Если и после этого не хватает — берутся вопросы, у которых плоха только цитата (цитата скрывается, на экране предупреждение). Если всё равно меньше — честное предупреждение «Получилось X из N».
   - варианты перемешиваются кодом (ИИ любит ставить правильный первым), подсказки остаются только у «вне файла» / «на логику» и только если включены.
3. **Если сервер упал посреди работы:** задача раз в 20 с отмечается в базе (`heartbeat_at`). Нет отметки дольше `JOB_STALE_SECONDS` (120 с) → статус «ошибка» + «Повторить».

**Квиз по предмету:** `create_subject_quiz` берёт `SUBJECT_OLD_SHARE` (50 %) старых вопросов предмета — сначала те, где последний ответ был неверным, потом те, на которые ещё не отвечал, потом остальные (сначала той же сложности). Остальное — новые вопросы от ИИ по всем сохранённым текстам предмета (если текстов много — по кускам из разных мест), не похожие на старые. Кнопка есть всегда, даже при одном квизе.

**Замена вопроса:** запрос `replace` с одним слотом: та же тема, подтема и сложность, но **другой вид** вопроса; в запросе — все прошлые варианты и остальные вопросы квиза, чтобы не повторялся. Если ИИ прислал похожий/неправильный вопрос — одна автоматическая повторная попытка; не вышло — замена **не засчитывается** и об этом прямо пишется. Лимит — `MAX_REPLACES` (4) на вопрос.

**Разнообразие вопросов:** код составляет план на каждый вопрос — вид + «подход» (причина и следствие, сравнение, применение к ситуации, найди ошибку, что будет если, пример/контрпример, связь тем…). Подходы зависят от сложности, список — `ANGLES` в `app/quiz/prompts.py`.

**Разбор ошибок:** в итоге у красных карточек сразу виден правильный ответ и объяснение. Кнопка «Разобрать ошибки» — один запрос `review`: по каждой теме с ошибками ИИ пишет суть простыми словами, что запомнить, где была ошибка, пример и что перечитать (цитата). Разбор сохраняется в попытке (`attempts.review`) — второй раз не платим. Код — `review_attempt` в `pipeline.py`, промпт — `review_prompt`.

**Открытый ответ:** `check_open` → 0 / 0,5 / 1 + комментарий. Если ИИ не ответил — на карточке «Не удалось проверить. Засчитать? / Наполовину / Не засчитывать / Проверить ещё раз».

## 7. Виды вопросов (`app/quiz/questions.py`)

| Вид | Как проверяется | Баллы |
|---|---|---|
| single — один из 4 | код | 1 |
| multi — несколько | код, частичные баллы: (верные − лишние) / все верные | 2 |
| tf — верно/неверно | код | 1 |
| open — своими словами | ИИ: 0 / ½ / 1 | 2 |
| match — соответствие | код, доля верных пар | 2 |
| order — порядок шагов | код, доля шагов на своём месте | 2 |
| fill — вставить пропущенное | код, допускает 1 опечатку в словах от 5 букв | 1 |

**Зелёная карточка** — только полностью верно. Частично — красная с пометкой «½ частично», баллы идут в счёт.

**Пометки:** `outside` («вне файла») и `logic` («на логику»). Подсказки бывают только у них.

## 8. ИИ (`app/ai/`)

- Провайдер берётся из Настроек (таблица settings), если там пусто — из `AI_PROVIDER`.
- Ключ: из Настроек (зашифрован `KEY_SECRET`), если там нет — из переменных окружения.
- **YandexGPT без ключа:** если API-ключ не задан, а приложение работает в Yandex Cloud с сервисным аккаунтом, берётся его временный токен из метаданных 🟡.
- `ask_json(purpose, …)`: убирает ```json, вырезает `{…}`, чинит лишние запятые, разворачивает `{"quiz": {...}}`, понимает синонимы полей (`question`/`вопрос`, `options`/`варианты`/`choices`, правильный ответ буквой «Б», номером с 1, текстом варианта…), числа строкой («0,5 балла»). Не вышло — повторный запрос «верни только JSON». Каждый вызов пишется в `usage`.
- Ошибки переводятся в понятные: «ключ не подошёл», «нет денег / нет платёжного аккаунта», «лимит запросов (например, 10 бесплатных в час)», «нет связи».
- Purpose: `quiz`, `replace`, `check_open`, `subject_quiz`, `ping`.

## 9. Внешний вид

- Все цвета — CSS-переменные, 10 палитр в начале `static/app.css`. Палитра хранится на сервере и в памяти браузера (чтобы при запуске не мигало).
- Подсветка ответа: мягкий фон (`--ok-bg` / `--bad-bg`) + толстая рамка (`--ok` / `--bad`) + значок ✓/✕ и слово «Верно»/«Неверно» — заметно в любой палитре, не только по цвету. Контраст всех палитр проверяет `python scripts/check_contrast.py`.
- **Карточки** — раздел «5. КАРТОЧКИ» в `app.css`: `--card-radius`, `--card-pad`, `--card-border`, `--card-shadow`, `--card-anim`. Настройку вида карточек в приложении сделаем потом — всё уже вынесено в переменные.
- Цвет строки состояния iPhone (`theme-color`) меняется вместе с палитрой.

## 10. «Как приложение» (PWA)

- `sw.js` кэширует оболочку: экран входа и меню появляются сразу, даже пока сервер просыпается. Новая версия скачивается в фоне и видна со **следующего** запуска (закрыл и открыл приложение).
- Пока сервер молчит дольше 1,5 с — надпись «подключаюсь… сервер просыпается».
- Отступы под «чёлку» и полоску внизу — `env(safe-area-inset-*)`.
- Внешние ссылки открываются в новом окне.
- **Скорость пробуждения:** локально контейнер отвечает через ~1,5 с после запуска; в Yandex Cloud добавится запуск экземпляра 🟡 (ожидаем 2–6 с после долгого простоя). Что уже сделано для скорости: лёгкий образ (python-slim, ~97 МБ в сжатом виде), тяжёлые библиотеки грузятся только когда нужны, байткод заранее скомпилирован.

## 11. Безопасность

- Пароль: `KVIZY_PASSWORD`; если сменили в Настройках — хэш (scrypt) в базе, он главнее.
- Cookie подписана HMAC (`SESSION_SECRET`), в подпись входят «отпечаток» пароля и версия сессии → смена пароля = все **другие** устройства выходят (текущее сразу получает новую cookie).
- 5 ошибок входа за 5 минут с одного адреса → пауза.
- Загрузки: тип по расширению и сигнатуре, до 15 МБ, файл реально открывается.

## 11а. Тестеры (другие люди)

- Владелец в Настройках → «Тестеры» создаёт аккаунт: имя, логин, лимит на ИИ в месяц (по умолчанию 50 ₽ — `GUEST_LIMIT_RUB` в `app/auth.py`). Пароль придумывает приложение и показывает **один раз**.
- Тестер входит с логином и паролем. Владелец входит без логина (поле пустое).
- У каждого свои квизы, предметы, статистика, палитра. Чужое не видно даже по прямой ссылке (`_own()` в `app/api/routes.py` → 404).
- ИИ у всех общий — владельца. Настройки ИИ, бюджет и расходы видит и меняет только владелец (`auth.require_owner`). В расходах есть разбивка «По людям».
- Лимит тестера: `check_quota()` в `app/ai/__init__.py` перед каждым запросом к ИИ. Исчерпан — квиз не создаётся, замена не работает, открытый ответ предлагается засчитать вручную. С 1-го числа счётчик обнуляется. У владельца лимита нет.
- Можно: поменять лимит, сделать новый пароль (старые входы тестера сразу перестают работать), выключить (тестер сразу выходит), удалить (стираются все его данные; расходы остаются в статистике).
