# Ошибки KvizY и выводы

Все ошибки, которые случились за время создания и запуска KvizY, в одном списке. По каждой: что было, почему, как исправили и какой из этого урок на будущее.
Ошибки разложены по группам. В конце — короткий список правил, которые стоит соблюдать в следующих проектах.

---

## 1. Запуск в Yandex Cloud (деплой)

### 1.1. Лишний перенос строки в секрете сломал сборку
- **Что было:** деплой упал с ошибкой `invalid reference format`: адрес образа получился вида `cr.yandex/crp…\n/kvizy`.
- **Почему:** при копировании ID реестра в секрет GitHub в конец попал перенос строки. Код взял значение как есть.
- **Как исправили:** деплой сам убирает пробелы и переносы строк из всех секретов перед использованием.
- **Урок:** любой ввод человека (секреты, ID, пароли) нужно чистить от пробелов и переносов. Не надеяться, что скопируют идеально.

### 1.2. Роботу не хватило прав сделать контейнер публичным
- **Что было:** шаг `allow-unauthenticated-invoke` упал с `Permission denied`.
- **Почему:** сделать контейнер публичным может только роль `admin`, а у сервисного аккаунта была `editor`. Этого не было в плане.
- **Как исправили:** включили «Публичный контейнер» один раз вручную в консоли. Шаг в деплое сделали необязательным (предупреждение вместо падения). Добавили шаг 7.5 в инструкцию.
- **Урок:** перед планом деплоя сверять каждую команду с нужной ролью. Разовые админские действия лучше делать руками, чем давать роботу лишние права.

### 1.3. Не хватало пакета `requests` — приложение падало при запуске
- **Что было:** по адресу приложения отвечало `{"errorMessage":"exit status 3"}`.
- **Почему:** библиотеке YDB для входа через сервисный аккаунт (метаданные Yandex Cloud) нужен пакет `requests`, а его не было в `requirements.txt`. Локально этот путь не проверялся: там база подключалась без ключа.
- **Как исправили:** добавили `requests`. Проверили в собранном образе, что подключение «как в облаке» создаётся.
- **Урок:** проверять в контейнере тот путь, по которому код пойдёт **на сервере** (те же ключи и способ входа), а не только локальный.

### 1.4. При ошибке базы приложение падало молча
- **Что было:** причину падения из 1.3 не было видно ни в браузере, ни в логе деплоя. Только `exit status 3`.
- **Почему:** если база была недоступна, сервер падал при старте и не успевал ничего сказать.
- **Как исправили:** сервер больше не падает. Ошибку базы целиком показывают `/api/health` и любой запрос к API (код 503 + текст).
- **Урок:** «ошибки не молчат» касается и запуска: сервер должен подняться и показать, что сломано.

### 1.5. Проверка `/api/health` в деплое не печатала ответ
- **Что было:** деплой писал только «не ответило», без причины.
- **Как исправили:** деплой печатает код и текст ответа при каждой попытке. Именно так нашли причину 1.3.
- **Урок:** любая автоматическая проверка должна показывать, **что именно** она получила.

### 1.6. Миграция базы не работала в YDB (поймали до выкатки)
- **Что было:** добавление новых полей в существующую таблицу (`ALTER TABLE … ADD COLUMN`) падало: «Scheme operations cannot be executed inside transaction».
- **Почему:** в YDB изменения схемы нельзя выполнять внутри транзакции. Обычный `text()` и режим `AUTOCOMMIT` там не помогают.
- **Как исправили:** запросы изменения схемы идут через `sa.DDL(...)` — YDB выполняет их отдельно. Проверили на локальной YDB со **старой** структурой базы, как на сервере.
- **Урок:** миграции проверять на копии базы со старой схемой, а не только на новой пустой.

## 2. Логика квизов

### 2.1. Замена вопроса падала: «нет образца ответа»
- **Что было:** при замене открытого вопроса YandexGPT положил образец ответа не в то поле. Проверка отбраковала вопрос.
- **Почему:** разбор ответа ИИ искал образец только в двух-трёх полях.
- **Как исправили:** образец ищется во всех похожих полях: `reference`, `sample_answer`, `answer`, `correct` (строкой, списком или объектом). Если его нет совсем — берётся из ключевых мыслей или объяснения. В промпт добавили «ОБЯЗАТЕЛЬНО reference». Замена делает одну автоматическую повторную попытку.
- **Урок:** ответы ИИ разбирать терпимо **по каждому полю**, а не только по общей форме JSON. Если обязательного поля нет — иметь запасной вариант.

### 2.2. Замена давала вопрос того же вида
- **Что было:** заменённый вопрос оставался того же формата, а нужно было менять и формат.
- **Почему:** в задании было «той же темы, типа и сложности». Желание поменялось после живого использования.
- **Как исправили:** новый вопрос всегда **другого** вида, тема и сложность те же.
- **Урок:** после первого живого использования пересматривать правила из ТЗ. Живой опыт важнее исходного текста.

### 2.3. Замена повторяла вопросы, которые уже есть в квизе
- **Что было:** (в тестах) новый вопрос совпадал с другим вопросом того же квиза, и замена не засчитывалась.
- **Почему:** ИИ не говорили, какие ещё вопросы есть в квизе.
- **Как исправили:** в запрос замены передаются прошлые варианты и остальные вопросы квиза.
- **Урок:** чтобы ИИ не повторялся, ему нужно **показать**, что уже есть.

### 2.4. Вопросы были однотипными
- **Что было:** много «Что такое…», мало вопросов на понимание.
- **Почему:** ИИ получал только «сколько каких видов» и дальше выбирал самый простой шаблон.
- **Как исправили:** код составляет план на **каждый** вопрос — вид и подход (причина и следствие, сравнение, применение, найди ошибку, что будет если, пример или контрпример, связь тем). Подходы зависят от сложности. Не больше двух вопросов с одинаковым началом. Неправильные варианты — правдоподобные.
- **Урок:** общие пожелания («на понимание») ИИ выполняет плохо. Конкретный план на каждый пункт выполняет хорошо.

### 2.5. Не было понятного разбора ошибок
- **Что было:** объяснение пряталось за тапом, а углубления в тему не было.
- **Как исправили:** у красных карточек сразу видны правильный ответ и объяснение. Объяснение стало полнее: почему верно, почему ловушка неверна, что запомнить. Добавили кнопку «Разобрать ошибки»: ИИ по каждой теме объясняет суть, что запомнить, где ошибка, пример и что перечитать. Разбор сохраняется.
- **Урок:** главная польза квиза для учёбы — в разборе ошибок. Его нужно показывать сразу, а не прятать.

## 3. Интерфейс

### 3.1. Системная кнопка выбора файлов — английская и мелкая
- **Как исправили:** своя большая кнопка «Выбрать файлы».
- **Урок:** стандартные поля браузера на iPhone смотрятся чужеродно — оборачивать в свои кнопки.

### 3.2. Мелкие подписи на графике роста
- **Почему:** график был нарисован широким, на телефоне он сжимался, а с ним и текст.
- **Как исправили:** график сделан под ширину телефона, шрифт крупнее.
- **Урок:** смотреть каждый экран на ширине iPhone, а не только на компьютере.

### 3.3. Баллы вида «0.666 из 2»
- **Как исправили:** везде округление до десятых, с запятой.
- **Урок:** любые дробные числа на экране округлять.

## 4. Проверка и тесты

### 4.1. Тест с неоднозначным ответом
- **Что было:** тест ждал, что номера `1, 3` означают «первый и третий». Но при 4 вариантах это может быть и нумерация с нуля.
- **Как исправили:** поправили тест: код прав, тест был неоднозначным.
- **Урок:** если тест падает — сначала проверить, однозначен ли сам тест.

### 4.2. Ошибки в скриптах скриншотов (не в приложении)
- Палитра не менялась: скрипт менял её только в памяти браузера, а главный источник — сервер. Правильно.
- Подсказки «пропали»: форма запомнила прошлое значение, и скрипт его выключил.
- Квиз не перезагружался: переход на тот же адрес не обновляет страницу.
- **Урок:** прежде чем чинить приложение по скриншоту, проверить, не врёт ли сам скрипт проверки.

### 4.3. Окружение для проверки
- Свежая локальная YDB в Docker падала (нет IPv6 в песочнице) — взяли версию 24.3.
- Сборка образа в песочнице не видела сертификат прокси — для локальной сборки добавляли его отдельно, в настоящий `Dockerfile` он не попал.
- Докер в песочнице перезапускался — поднимали заново.
- **Урок:** проблемы окружения отделять от проблем кода и не тащить обходные пути в настоящие файлы.

## 5. Настройка Yandex Cloud и GitHub (шаги владельца)

Это не ошибки кода, а места, где инструкция была недостаточно понятной.

| Что случилось | Как исправили | Вывод для инструкции |
|---|---|---|
| Вместо сервисного аккаунта открылось «Создание облака» | Отменили, нашли кнопку «Создать сервисный аккаунт» | Писать, **какую** кнопку нажимать и что «Создать ресурс» — общее меню |
| Все значения легли в один секрет `KVIZY` | Удалили, сделали 9 отдельных | Сразу давать каждую пару «имя → значение» отдельными блоками для копирования |
| Непонятно, откуда взять текст ключа JSON | Пошагово: «Файлы» → открыть → «Выбрать все» → «Скопировать» | Для iPad всегда описывать, как скопировать текст из файла |
| Непонятно, зачем `SESSION_SECRET` и `KEY_SECRET` и что туда писать | Объяснили простыми словами | Объяснять назначение каждого секрета прямо в инструкции |
| Не нашлось «Соединение» у базы | Подсказали вкладку «Обзор» | Давать скриншот или точный путь до поля |
| Шага «Публичный контейнер» не было в плане | Добавили шаг 7.5 | См. 1.2 |

## 6. Правила на будущее (коротко)

1. **Чистить ввод** — секреты, ID, пароли: убирать пробелы и переносы строк.
2. **Сервер не падает молча** — при любой ошибке запуска поднимается и показывает причину на `/api/health`.
3. **Проверки печатают ответ** — не просто «упало», а что именно пришло.
4. **Проверять «как на сервере»** — тот же способ входа, те же ключи, собранный образ.
5. **Миграции — на старой схеме**: копия базы со старыми таблицами, потом новая версия.
6. **Права — заранее**: каждую команду деплоя сверять с ролью. Разовые админские шаги делать руками.
7. **Ответы ИИ — терпимо по каждому полю** и с запасным вариантом, если поля нет.
8. **ИИ — конкретный план**, а не общие пожелания. Показывать ему, что уже есть, чтобы не повторялся.
9. **Разбор ошибок — сразу на виду**: это главная польза для учёбы.
10. **Каждый экран — на ширине iPhone**, числа округлять, системные элементы оборачивать в свои.
11. **Сначала проверить тест или скрипт проверки**, потом чинить код.
12. **Инструкции для iPad**: точная кнопка, точное поле, каждая пара «имя → значение» отдельно, как скопировать из файла.
13. **После первого живого использования** пересматривать правила из ТЗ.
